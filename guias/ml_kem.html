L2.2Parte A · K-PKE de juguete con NumPy

Implementará el cifrado subyacente de ML-KEM con los parámetros reales (n = 256, q = 3329, k, η₁, η₂, du, dv), pero con dos simplificaciones deliberadas: multiplicación de polinomios ingenua en lugar de NTT y aleatoriedad de NumPy en lugar de SHAKE. No hay transformación FO: es solo la capa IND-CPA.

A.1 · Aritmética en el anillo

El producto en ℤq[X]/(Xn + 1) es una convolución seguida de un plegado negacíclico: como Xn = −1, el coeficiente de grado n + i se resta del de grado i.

import numpy as np

Q, N = 3329, 256
rng = np.random.default_rng()

def polymul(a, b):
    """Producto en Z_q[X]/(X^n + 1): convolución y plegado negacíclico."""
    n = len(a)
    c = np.convolve(a.astype(np.int64), b.astype(np.int64))   # grado ≤ 2n − 2
    res = c[:n].copy()
    res[: n - 1] -= c[n:]                                     # X^n = −1
    return res % Q

def matvec(A, v, transpose=False):
    k = len(v)
    return np.array([sum(polymul(A[j][i] if transpose else A[i][j], v[j]) for j in range(k)) % Q
                     for i in range(k)])

def dot(a, b):
    return sum(polymul(x, y) for x, y in zip(a, b)) % Q

A.2 · Ruido, compresión y K-PKE

def cbd(eta, shape):
    """Binomial centrada: suma de η bits menos suma de otros η bits."""
    bits = rng.integers(0, 2, size=shape + (2, eta))
    return bits[..., 0, :].sum(-1) - bits[..., 1, :].sum(-1)

def compress(x, d):      # ⌈(2^d/q)·x⌋ mod 2^d, con aritmética entera
    return ((x.astype(np.int64) << (d + 1)) + Q) // (2 * Q) % (1 << d)

def decompress(y, d):    # ⌈(q/2^d)·y⌋
    return (y.astype(np.int64) * 2 * Q + (1 << d)) >> (d + 1)

def centered(x):
    x = x % Q
    return np.where(x > Q // 2, x - Q, x)

def keygen(k, eta1):
    A = rng.integers(0, Q, size=(k, k, N))       # en FIPS 203: SHAKE128(ρ), dominio NTT
    s, e = cbd(eta1, (k, N)), cbd(eta1, (k, N))
    t = (matvec(A, s) + e) % Q
    return (A, t), s

def encrypt(pk, m, k, eta1, eta2, du, dv):
    A, t = pk
    y, e1, e2 = cbd(eta1, (k, N)), cbd(eta2, (k, N)), cbd(eta2, (N,))
    u = (matvec(A, y, transpose=True) + e1) % Q
    v = (dot(t, y) + e2 + decompress(m, 1)) % Q   # ⌈q/2⌋·m = 1665·m
    return compress(u, du), compress(v, dv)

def decrypt(s, c, du, dv):
    cu, cv = c
    u, v = decompress(cu, du), decompress(cv, dv)
    w = (v - dot(s, u)) % Q
    return compress(w, 1), w

L2.4Parte C · Validación con vectores ACVP de NIST

El programa de validación de algoritmos criptográficos de NIST (CAVP) publica sus vectores de prueba en formato JSON en el repositorio usnistgov/ACVP-Server. El fichero internalProjection.json de cada conjunto contiene entradas y resultados esperados. Para ML-KEM hay dos: generación de claves (entradas d, z; salidas ek, dk) y encapsulamiento/desencapsulamiento (incluye cifrados modificados que deben producir la clave de rechazo implícito, y comprobaciones de claves mal formadas).

$ B=https://raw.githubusercontent.com/usnistgov/ACVP-Server/master/gen-val/json-files
$ for d in ML-KEM-keyGen-FIPS203 ML-KEM-encapDecap-FIPS203; do
    mkdir -p acvp/$d && curl -s -o acvp/$d/internalProjection.json $B/$d/internalProjection.json
  done
"""Comprueba ML-KEM (pyca y liboqs) contra los vectores ACVP de NIST."""
import json
from pathlib import Path
from cryptography.hazmat.primitives.asymmetric import mlkem
import oqs

load = lambda name: json.loads((Path("acvp") / name / "internalProjection.json").read_text())
PYCA = {"ML-KEM-768": mlkem.MLKEM768PrivateKey, "ML-KEM-1024": mlkem.MLKEM1024PrivateKey}

ok = fail = 0
for g in load("ML-KEM-keyGen-FIPS203")["testGroups"]:
    ps = g["parameterSet"]
    for t in g["tests"]:
        seed = bytes.fromhex(t["d"] + t["z"])          # semilla de 64 bytes = d ‖ z
        ek, dk = bytes.fromhex(t["ek"]), bytes.fromhex(t["dk"])
        if ps in PYCA:
            good = PYCA[ps].from_seed_bytes(seed).public_key().public_bytes_raw() == ek
            ok += good; fail += not good
        with oqs.KeyEncapsulation(ps) as kem:
            good = kem.generate_keypair_seed(seed) == ek and kem.export_secret_key() == dk
            ok += good; fail += not good
print(f"keyGen: {ok} correctos, {fail} fallos")

ok = fail = 0
for g in load("ML-KEM-encapDecap-FIPS203")["testGroups"]:
    if g["function"] not in ("encapsulation", "decapsulation"):
        continue
    for t in g["tests"]:
        with oqs.KeyEncapsulation(g["parameterSet"], bytes.fromhex(t["dk"])) as kem:
            good = kem.decap_secret(bytes.fromhex(t["c"])) == bytes.fromhex(t["k"])
        ok += good; fail += not good
print(f"decaps: {ok} correctos, {fail} fallos")
keyGen: 125 correctos, 0 fallos
decaps: 105 correctos, 0 fallos

Pista para C.2

Para ML-KEM con parámetro k, dk = dkPKE (384k bytes) ‖ ek (384k + 32) ‖ H(ek) (32) ‖ z (32). hashlib.shake_256(z + c).digest(32) debe coincidir con t["k"]. Para un cifrado válido, en cambio, no coincidirá.

L2.5Parte D · Rechazo implícito y canales laterales

import statistics, time
from cryptography.hazmat.primitives.asymmetric import mlkem

sk = mlkem.MLKEM768PrivateKey.generate()
ss, ct = sk.public_key().encapsulate()
bad = bytearray(ct); bad[100] ^= 0x01; bad = bytes(bad)
print(sk.decapsulate(ct) == ss, sk.decapsulate(bad) == ss)   # True False, sin excepción
print(sk.decapsulate(bad) == sk.decapsulate(bad))            # True: K̄ es determinista

def muestras(c, n=20000):
    out = []
    for _ in range(n):
        t0 = time.perf_counter_ns(); sk.decapsulate(c); out.append(time.perf_counter_ns() - t0)
    return out
print(statistics.median(muestras(ct)), statistics.median(muestras(bad)))

Orientación para el profesorado

D.1: ataques de reacción / oráculo de validez; con fuga temporal el oráculo reaparece. D.2: una diferencia de medianas en un sistema multitarea no prueba nada en ninguno de los dos sentidos; hay que aislar el núcleo, fijar frecuencia, intercalar clases y usar un contraste sobre muchas muestras. D.3: poly_tomsg (KyberSlash1) y poly_compress/polyvec_compress (KyberSlash2); la reencriptación en Decaps procesa m′, derivado del secreto. D.4: hay que verificar el código máquina (p. ej., herramientas tipo Valgrind con memoria «secreta» marcada, como la que usaron los autores de KyberSlash, o verificación formal). D.5: fallos de descifrado frecuentes permiten ataques que buscan cifrados con más probabilidad de fallar y aprenden el secreto de las respuestas; por eso FIPS 203 exige ≤ 2−138,8.

Ideas clave
  • K-PKE cabe en unas decenas de líneas; lo que lo hace correcto es el margen entre el ruido (unos cientos) y q/4 ≈ 832.
  • Las bibliotecas difieren en detalles que rompen la interoperabilidad: orden de la tupla, formato de clave (semilla de 64 bytes o clave expandida) y conjuntos disponibles.
  • ML-KEM-768 cuesta decenas de microsegundos, comparable a X25519; su coste real es el tamaño (1 184 + 1 088 bytes).
  • Los vectores ACVP permiten validar una implementación bit a bit, incluido el rechazo implícito; la ausencia de canales laterales, en cambio, hay que comprobarla sobre el binario.
